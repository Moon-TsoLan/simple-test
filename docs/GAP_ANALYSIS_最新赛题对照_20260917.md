**任务一专项问题**：
1. **v0.2 有 29 篇任务一实体为空**（本地请求失败）、9 篇任务二失败——官方评测中直接损失召回率，必须补跑/修复；
2. **`category_code` 误填「品目号」**（4B 已确认）——新赛题术语表明确定义"品目：按政府采购品目分类目录划分的类别"，此 bug 正撞在评分字段上；
3. `brand_supplier` 混装品牌/制造商/产品供应商——新赛题把「品牌（产品供应商）」合并为一个字段且术语表定义为"标的物的品牌提供方"，语义上可辩护，但需在文档中明确口径。

**Neo4j 偏差说明**：新赛题知识背景明确列出"知识图谱构建、图数据建模与图检索增强技术"并两次点名 Neo4j/图检索增强。虽为"推荐"而非硬性（技术栈合规性只查 Vue+Python），但：
- 方案 A（低成本）：SQLite 保持权威源，增加 Neo4j 投影层用于关系建模展示与图检索（Cypher 实现五场景查询），文档中体现"图数据建模"；
- 方案 B（辩护式）：维持 SQLite 预计算 + 文档论证选型理由（免部署、离线、查询快）。
- 建议：决赛技术创新分与答辩追问下，方案 A 的展示价值更高；工作量约 2-4 天。

## 6. 评分口径对齐清单（容易丢分的隐蔽点）

| 官方定义 | 当前口径差距 |
|---|---|
| 提取准确性 = 准确率×0.4+精确率×0.3+召回率×0.3 | 当前只有"严格全字段一致率/字段一致率"，**需开发按官方三指标定义的评测脚本**（实体级+字段级 P/R/A），并在金标上跑出基线 |
| 处理速率从**数据集导入完成**起算，至**全部结果写库**止 | 即上传流水线的端到端总耗时；当前无整批计时埋点，本地 4B 速度完全无法参评（见任务一） |
| 查询效率含**前端渲染完成** | 需浏览器端实测口径 |
| 场景结果**与官方基准数据比对** | 官方基准口径未知（TOP5 并列怎么取、金额取中标金额还是报价、是否含无效标）——需提前设计"口径开关"使统计口径可配置对齐 |
| 排名赋分"就高不就低" | 边界规则利好，无需行动 |
| 模型版本与参数规模声明 | 需在文档明确：批处理 qwen3.5-9b、运行时 qwen3-4b-2507（或最终切平台标准资源后的型号） |

## 7. 优先行动建议（按投入产出排序）

1. **处理速率攻坚（最高优先）**：评测在云平台+官方 API 资源上跑——把流水线后端从本地 4B 切到平台标准模型资源（OpenAI 兼容，代码已支持 `--backend api`），加并发与批量；本地模型保留为离线备份。目标：1000 篇总耗时有数量级改善；
2. **官方数据薄适配器**：数据格式与自建 291 篇同构（HTML+ZIP），按既有 manifest 契约写 `official_adapter.py`；
3. **补跑 v0.2 失败篇**：任务一 29 篇空实体 + 任务二 9 篇 failed；
4. **修复 `category_code` 品目号 bug**：正撞评分字段；
5. **建立官方口径评测脚本**：准确率/精确率/召回率三指标 + 任务二人工关系金标（优先多包、联合体、长表样本）；
6. **查询效率按官方口径实测**：浏览器端计时五场景，补 P50/P95；
7. **技术路线对比分析报告 + 数据质量分析报告**：素材已齐，先成文（过程性分确定性高）；
8. **Neo4j 投影层**（可选增强）：SQLite 权威源不变，加 Neo4j 图建模展示与图检索；
9. **云平台部署包**：Linux 一键启动、依赖清单、评审账号与操作说明；
10. **设计文档、PPT、双视频**：最后统一产出。
